GPX format specification

This document describes the radiation-related GPX 1.1 extensions written by GeigerGPX. Tags are grouped by their placement in metadata, track points, and waypoints. Each entry specifies the value’s meaning, units, serialization, and usage.

Namespace

Standard GPX elements use the GPX 1.1 namespace. Radiation extension elements use the GeigerGPX namespace URI https://github.com/bocovp/GeigerGPX. The rad prefix is conventional; any prefix bound to that URI is equivalent. XML tag names are case-sensitive.

XML · namespace declaration
<gpx version="1.1" creator="GeigerGPX"
     xmlns="http://www.topografix.com/GPX/1/1"
     xmlns:rad="https://github.com/bocovp/GeigerGPX">
  <!-- Radiation elements are placed inside GPX extensions. -->
</gpx>
metadata/extensionsTrack summaries and detector calibration.
trk/trkseg/trkpt/extensionsMeasurement values for a track-point window.
wpt/extensionsStandalone measurement values and detector name.

The extension tags belong inside the GPX extensions element of the stated parent. Examples below assume the namespace declarations shown above. Numeric values use a period as the decimal separator, without unit text or thousands separators. “Always written” refers to the current exporter; older files may omit fields.

Metadata

Location: gpx/metadata/extensions

These extensions summarize the exported track and store its detector calibration. Summaries are recalculated from the retained track points when the track is exported, including after cropping or splitting.

<rad:pointcount>

Number of trkpt elements stored in the exported track, including points with invalid coordinates. Waypoints are excluded.

The exporter always writes this field and recalculates it from the stored point list.

Value type
Non-negative integer
Unit
Track points
Serialization
Integer
XML · metadata / rad:pointcount
<metadata>
  <extensions>
    <rad:pointcount>2</rad:pointcount>
  </extensions>
</metadata>

<rad:distance>

Sum of the geographic distances between successive valid track points, calculated using Android’s Location.distanceBetween.

Points marked with <fix>none</fix> are skipped. Distance is measured directly from the previous valid point to the next valid point. With fewer than two valid points, the value is zero.

The exporter always writes this field.

Value type
Non-negative decimal
Unit
Metres
Serialization
3 decimal places
XML · metadata / rad:distance
<metadata>
  <extensions>
    <rad:distance>0.000</rad:distance>
  </extensions>
</metadata>

<rad:counts>

Sum of detector counts over all stored track points, including points with invalid coordinates. This is a track total rather than the count at a single point.

Counts and measurement duration are stored so a confidence interval can be calculated for the recorded series.

The exporter always writes this field.

Value type
Non-negative 64-bit integer
Unit
Counts
Serialization
Integer
XML · metadata / rad:counts
<metadata>
  <extensions>
    <rad:counts>150</rad:counts>
    <rad:seconds>90.000</rad:seconds>
  </extensions>
</metadata>

<rad:seconds>

Sum of the measurement durations of all stored track points, including points with invalid coordinates. This value is not the difference between the first and last point timestamps.

Duration provides the observation time required for count-rate and confidence-interval calculations.

The exporter always writes this field. Individual durations and the total are rounded independently, so their serialized sums may differ slightly.

Value type
Non-negative decimal
Unit
Seconds
Serialization
3 decimal places
XML · metadata / rad:seconds
<metadata>
  <extensions>
    <rad:counts>150</rad:counts>
    <rad:seconds>90.000</rad:seconds>
  </extensions>
</metadata>

<rad:dose>

Estimated accumulated dose over all stored track points, including measurement windows recorded without valid coordinates.

The exporter calculates dose = total counts / sensitivity / 3600. The factor 3600 converts hours to seconds. This calculation uses counts and calibration rather than rounded point dose rates.

The field is omitted when sensitivity is exactly 1.0, which is used for count-rate mode. A small nonzero dose may round to 0.000.

Value type
Non-negative decimal
Unit
µSv
Serialization
3 decimal places
XML · metadata / rad:dose
<metadata>
  <extensions>
    <rad:counts>150</rad:counts>
    <rad:dose>0.004</rad:dose>
    <rad:sensitivity dimension="cps/uSv/h">10.0</rad:sensitivity>
  </extensions>
</metadata>

<rad:device>

Human-readable name of the radiation detector selected for recording the track.

The exporter writes this field only when the device name is nonblank. The name is a label; calibration is stored separately in rad:sensitivity. XML-sensitive characters in the name are escaped.

Value type
XML-escaped text
Unit
Not applicable
Serialization
Text
XML · metadata / rad:device
<metadata>
  <extensions>
    <rad:device>RADEX RD1008</rad:device>
  </extensions>
</metadata>

<rad:sensitivity>

Detector count rate in counts per second corresponding to a dose rate of 1 µSv/h. The calibration relation is dose rate = count rate / sensitivity.

The exporter always writes the literal attribute dimension="cps/uSv/h", meaning cps / (µSv/h). The current reader parses the positive numeric value and does not inspect this attribute. Missing or non-positive values fall back to 10.0.

A value of 1.0 is used for count-rate mode; accumulated dose is omitted in this mode.

Value type
Positive decimal
Unit
cps / (µSv/h)
Serialization
Up to 6 decimal places; at least 1
XML · metadata / rad:sensitivity
<metadata>
  <extensions>
    <rad:sensitivity dimension="cps/uSv/h">10.0</rad:sensitivity>
  </extensions>
</metadata>

<rad:edited>

Indicates that the track was saved through an editing operation, such as cropping, splitting, or marking coordinates as invalid.

The exporter writes true when the edited flag is set and omits the field otherwise. The reader treats case-insensitive true as edited; absence or other values are treated as false. The field does not record individual editing operations.

Value type
Boolean marker
Unit
Not applicable
Serialization
Literal true
XML · metadata / rad:edited
<metadata>
  <extensions>
    <rad:edited>true</rad:edited>
  </extensions>
</metadata>

Track points

Location: gpx/trk/trkseg/trkpt/extensions

Each trkpt represents a measurement window. Coordinates are averaged over that window when GPS samples are available, and the timestamp is its midpoint.

The exporter marks invalid coordinates with the standard GPX element <fix>none</fix>, directly inside trkpt. Such points retain their measurement values and contribute to metadata totals, but are excluded from distance calculations.

An optional app setting duplicates dose rate into GPX ele. In that case, the value is radiation data rather than elevation in metres. The reader uses rad:doserate and does not use ele as a radiation fallback.

<rad:doserate>

Mean dose rate over the measurement window represented by this track point. For calibrated measurements, doserate = counts / seconds / sensitivity, using the sensitivity stored in track metadata.

The exporter always writes this field. In count-rate mode, with metadata sensitivity 1.0, the numeric value corresponds to counts per second.

The track reader uses a positive stored dose rate. Otherwise, when duration is greater than 0.000001 seconds, it reconstructs the value from counts, duration, and metadata sensitivity.

Value type
Non-negative decimal
Unit
µSv/h for calibrated measurements
Serialization
5 decimal places
XML · track points / rad:doserate
<trkpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:00:30Z</time>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>120</rad:counts>
    <rad:seconds>60.000</rad:seconds>
  </extensions>
</trkpt>

<rad:counts>

Detector counts collected during this point’s rad:seconds measurement window. This is an interval count, not a cumulative track count.

Counts and duration are stored so confidence intervals can be calculated for one point or a series of points.

The exporter always writes this field. Counts include the configured counts-per-beep multiplier and may differ from the number of detected audio beeps. The multiplier is not exported.

Value type
Non-negative 32-bit integer
Unit
Counts
Serialization
Integer
XML · track points / rad:counts
<trkpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:00:30Z</time>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>120</rad:counts>
    <rad:seconds>60.000</rad:seconds>
  </extensions>
</trkpt>

<rad:seconds>

Duration of the measurement window during which this point’s counts were collected. A positive duration is required to calculate a count rate or confidence interval.

For newly recorded track points, GPX time represents the window midpoint. Window boundaries can therefore be reconstructed as time ± seconds / 2; duration should not be inferred from the difference between adjacent midpoint timestamps.

The exporter always writes this field.

Value type
Non-negative decimal
Unit
Seconds
Serialization
3 decimal places
XML · track points / rad:seconds
<trkpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:00:30Z</time>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>120</rad:counts>
    <rad:seconds>60.000</rad:seconds>
  </extensions>
</trkpt>

Waypoints

Location: gpx/wpt/extensions

Each wpt stores a standalone measurement or a location bookmark. Coordinates, time, and the description are stored in standard GPX attributes and elements; radiation data is stored in the waypoint’s extensions.

<rad:doserate>

Mean dose rate for the standalone measurement represented by this waypoint. The waypoint reader uses the stored value and does not reconstruct it from counts and duration.

The exporter always writes this field. No sensitivity tag is written in waypoint extensions. When counts, duration, and dose rate are positive and duration exceeds 0.000001 seconds, the app infers sensitivity as (counts / seconds) / doserate; otherwise it uses 10.0. For count-rate observations with inferred sensitivity 1.0, the numeric value corresponds to counts per second.

A location-only bookmark is written with zero dose rate, counts, and duration. It does not represent a measured zero radiation level.

Value type
Non-negative decimal
Unit
µSv/h for calibrated measurements
Serialization
5 decimal places
XML · waypoints / rad:doserate
<wpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:05:00Z</time>
  <name>Five-minute background measurement</name>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>600</rad:counts>
    <rad:seconds>300.000</rad:seconds>
  </extensions>
</wpt>

<rad:counts>

Detector counts collected during this waypoint’s standalone measurement. This value is not a total over other waypoints or track points.

Counts and duration allow a confidence interval to be calculated for the measurement.

The exporter always writes this field, including the configured counts-per-beep multiplier. A waypoint created without a measurement contains 0 counts and zero duration.

Value type
Non-negative 32-bit integer
Unit
Counts
Serialization
Integer
XML · waypoints / rad:counts
<wpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:05:00Z</time>
  <name>Five-minute background measurement</name>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>600</rad:counts>
    <rad:seconds>300.000</rad:seconds>
  </extensions>
</wpt>

<rad:seconds>

Duration of this waypoint’s standalone measurement. The waypoint timestamp is stored in GPX time; it does not define the measurement duration.

A positive duration is required for count-rate and confidence-interval calculations. A waypoint created without a measurement contains 0.000 seconds.

The exporter always writes this field.

Value type
Non-negative decimal
Unit
Seconds
Serialization
3 decimal places
XML · waypoints / rad:seconds
<wpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:05:00Z</time>
  <name>Five-minute background measurement</name>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>600</rad:counts>
    <rad:seconds>300.000</rad:seconds>
  </extensions>
</wpt>

<rad:device>

Human-readable name of the detector associated with this waypoint’s measurement. The value applies to this waypoint rather than the file as a whole.

The exporter writes this field only when the waypoint has more than zero counts and a nonblank device name. Location-only bookmarks therefore omit it. XML-sensitive characters in the name are escaped.

Value type
XML-escaped text
Unit
Not applicable
Serialization
Text
XML · waypoints / rad:device
<wpt lat="51.50070000" lon="-0.12460000">
  <time>2026-01-15T10:05:00Z</time>
  <name>Five-minute background measurement</name>
  <extensions>
    <rad:doserate>0.20000</rad:doserate>
    <rad:counts>600</rad:counts>
    <rad:seconds>300.000</rad:seconds>
    <rad:device>RADEX RD1008</rad:device>
  </extensions>
</wpt>

Complete examples

The following examples are complete GPX documents with illustrative values. Standard GPX children are arranged in schema order, including time before name in waypoints.

Track

Two adjacent measurement windows at the same coordinates, containing 120 counts over 60 seconds and 30 counts over 30 seconds. Metadata summarizes both points. The track is marked edited.

XML · track.gpx
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="GeigerGPX"
     xmlns="http://www.topografix.com/GPX/1/1"
     xmlns:rad="https://github.com/bocovp/GeigerGPX">
  <metadata>
    <extensions>
      <rad:pointcount>2</rad:pointcount>
      <rad:distance>0.000</rad:distance>
      <rad:counts>150</rad:counts>
      <rad:seconds>90.000</rad:seconds>
      <rad:dose>0.004</rad:dose>
      <rad:device>RADEX RD1008</rad:device>
      <rad:sensitivity dimension="cps/uSv/h">10.0</rad:sensitivity>
      <rad:edited>true</rad:edited>
    </extensions>
  </metadata>
  <trk>
    <trkseg>
      <trkpt lat="51.50070000" lon="-0.12460000">
        <time>2026-01-15T10:00:30Z</time>
        <extensions>
          <rad:doserate>0.20000</rad:doserate>
          <rad:counts>120</rad:counts>
          <rad:seconds>60.000</rad:seconds>
        </extensions>
      </trkpt>
      <trkpt lat="51.50070000" lon="-0.12460000">
        <time>2026-01-15T10:01:15Z</time>
        <extensions>
          <rad:doserate>0.10000</rad:doserate>
          <rad:counts>30</rad:counts>
          <rad:seconds>30.000</rad:seconds>
        </extensions>
      </trkpt>
    </trkseg>
  </trk>
</gpx>

Invalid coordinates

A track point recorded without valid coordinates. The standard GPX fix element flags the position; counts, duration, and dose remain included in metadata totals.

XML · gps-gap.gpx
<?xml version="1.0" encoding="UTF-8"?>
<gpx version="1.1" creator="GeigerGPX"
     xmlns="http://www.topografix.com/GPX/1/1"
     xmlns:rad="https://github.com/bocovp/GeigerGPX">
  <metadata>
    <extensions>
      <rad:pointcount>1</rad:pointcount>
      <rad:distance>0.000</rad:distance>
      <rad:counts>20</rad:counts>
      <rad:seconds>10.000</rad:seconds>
      <rad:dose>0.001</rad:dose>
      <rad:sensitivity dimension="cps/uSv/h">10.0</rad:sensitivity>
    </extensions>
  </metadata>
  <trk>
    <trkseg>
      <trkpt lat="0.00000000" lon="0.00000000">
        <time>2026-01-15T10:00:05Z</time>
        <fix>none</fix>
        <extensions>
          <rad:doserate>0.20000</rad:doserate>
          <rad:counts>20</rad:counts>
          <rad:seconds>10.000</rad:seconds>
        </extensions>
      </trkpt>
    </trkseg>
  </trk>
</gpx>
